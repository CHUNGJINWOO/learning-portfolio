# Python 신호 모델링과 OOP 노트북 안내

이 문서는 두 노트북의 실제 코드와 실행 순서를 복습하기 위한 안내입니다. 노트북의 저장된 출력과 사용자의 학습 완료는 별개의 사항입니다.

## 1. 사인파 모델링

[01_sin_modeling.ipynb](01_sin_modeling.ipynb)은 NumPy 배열과 Matplotlib 그래프를 사용합니다.

### 실행 흐름

1. `numpy`를 `np`, `matplotlib.pyplot`을 `plt`로 가져옵니다.
2. `np.arange(0, 6, 0.01)`로 0부터 6 **미만**까지 0.01초 간격의 시간 배열 `t`를 만들고 `shape`로 배열 크기를 살펴봅니다. `arange`의 마지막 값은 부동소수점 표현의 영향을 받을 수 있습니다.
3. `np.sin(np.pi * t)`를 배열 전체에 적용하고, `plt.plot(t, y)`와 `plt.show()`로 그래프를 표시합니다. 이어 다른 시간 배열과 계수를 사용한 그래프를 그립니다.
4. `draw_sin(t, A, f, b)` 함수를 정의하고 `draw_sin(t, 1, 1, 0)`을 호출합니다. 함수는 값을 그래프로 표시하며 명시적인 `return`은 없습니다.

### 실제 수식과 인자

함수의 실제 계산은 다음과 같습니다.

```text
y = A * sin(π * f * t) + b
```

- `t`: 시간값 배열. 호출 전 배열을 준비하므로 함수 자체는 샘플 간격을 정하지 않습니다.
- `A`: 진폭 계수. 절댓값은 중심선에서의 최대 변위입니다.
- `f`: 사인 함수 각도에 곱하는 계수입니다. 시간 단위가 초이고 `f > 0`이면 이 식의 실제 주파수는 `f / 2` Hz, 주기는 `2 / f`초입니다.
- `b`: 파형 전체를 위아래로 이동시키는 편향 또는 오프셋입니다.

일반적인 주파수 `f_hz`를 직접 사용하는 식은 `A * sin(2π * f_hz * t) + b`입니다. 따라서 두 식에서 `f_hz = f / 2`입니다. `f = 0`이면 파형은 시간에 따라 진동하지 않고, 음수 계수의 주파수 크기는 `|f| / 2` Hz입니다. 여기에는 별도 위상 인자가 없습니다. OOP 노트북의 `freq`는 `2π * freq * t`를 사용하므로 이 노트북의 `f`와 같은 숫자를 넣어도 같은 주파수라는 뜻은 아닙니다.

### 복습 질문

- **Q. `np.sin()`에 배열을 넣으면 어떤 일이 일어나나요?** A. 배열의 각 시간값에 대해 사인값을 계산한 배열이 만들어집니다. 그래서 시간과 계산 결과를 짝지어 그릴 수 있습니다.
- **Q. `f = 1`, 시간 단위가 초일 때 이 함수의 주파수는 얼마인가요?** A. 0.5 Hz입니다. 실제 각도 계수가 `π`이므로 일반형 `2π * 0.5 * t`와 같기 때문입니다.
- **Q. `b`는 무엇을 바꾸나요?** A. 모든 계산값에 같은 값을 더해 그래프의 중심선을 이동시킵니다.

## 2. 객체지향 클래스

[02_python_oop_class.ipynb](02_python_oop_class.ipynb)은 사인·코사인 계산을 클래스와 메서드로 구성합니다. `DrawSin` 계열 클래스의 실습이며 ROS 2 `Node`를 상속하지 않습니다.

### 핵심 용어

- **클래스와 인스턴스:** 클래스는 객체를 만들기 위한 정의이고, `DrawSin(1, 1, 0, 3)`으로 만든 값은 그 클래스의 인스턴스입니다.
- **`__init__()`과 `self`:** 인스턴스 생성 시 초기화 메서드가 호출됩니다. `self.amp`처럼 저장한 값은 해당 객체의 속성이며, 메서드는 `self`를 통해 그 객체의 상태에 접근합니다.
- **상속과 오버라이딩:** 자식 클래스는 부모의 속성과 메서드를 이어받을 수 있습니다. 자식이 같은 이름의 메서드를 다시 정의하면 해당 자식 객체에서 그 정의가 사용됩니다.
- **`super().__init__()`:** 자식의 초기화 과정에서 부모의 초기화 메서드를 호출합니다.
- **객체 확인:** `__dict__`는 인스턴스에 저장된 속성 딕셔너리를 보여주고, `__dir__()`은 객체에서 접근 가능한 이름 목록을 살펴보는 데 사용됩니다.

### 셀 순서에 따른 변화

1. 첫 `DrawSin`은 `amp`, `freq`, `bias`, `end_time`을 속성에 저장합니다. 인스턴스를 만들고 `__dict__`와 속성을 확인한 뒤 `end_time`을 바꿉니다.
2. 같은 이름의 `DrawSin`을 다시 정의해 `calc_sin()`과 `draw_sin()`을 추가합니다. `calc_sin()`은 0.01초 간격의 `self.t`를 만들고 `amp * sin(2π * freq * t) + bias`를 반환합니다. 속성 `freq`를 바꾸어 다시 그립니다.
3. `DrawSinusoidal(DrawSin)`은 `calc_cos()`와 `draw_cos()`를 추가합니다. 인스턴스에서 새 코사인 메서드와 상속받은 사인 메서드를 모두 호출합니다.
4. `DrawSinusoidal2`는 `draw_sin()`을 다시 정의하여 그래프 제목과 축 이름을 추가합니다. 이것이 메서드 오버라이딩입니다.
5. 첫 `DrawSinusoidal3` 정의의 생성자는 `self.ts`만 저장하며 부모 생성자를 호출하지 않습니다. 다음 정의에서는 `super().__init__(amp, freq, bias, end_time)`으로 부모 속성을 초기화하고 `self.ts`를 추가합니다. 노트북은 각 인스턴스의 `__dict__`를 확인합니다.
6. 마지막 `DrawSinusoidal3` 정의는 `calc_sin()`과 `draw_sin()`을 다시 정의합니다. 사인 계산은 전달된 `self.ts`를 간격으로 사용합니다. 그러나 상속받은 `calc_cos()`는 여전히 **0.01초** 간격을 사용합니다. 마지막 예제에서 전달한 `ts`는 `0.1`입니다.

같은 이름의 `class` 셀을 다시 실행하면 그 이름이 새 클래스 정의를 가리킵니다. 이미 만든 객체가 자동으로 새 클래스로 바뀌는 것은 아닙니다. 따라서 위에서 아래로 셀을 실행하고 어떤 정의로 객체를 만들었는지 확인하는 것이 중요합니다.

### 복습 질문

- **Q. `self.freq = 2`는 무엇을 바꾸나요?** A. 해당 인스턴스의 `freq` 속성입니다. 이후 그 객체의 계산 메서드는 바뀐 값을 사용합니다.
- **Q. 첫 `DrawSinusoidal3`에서 부모 속성이 초기화되지 않는 이유는 무엇인가요?** A. 자식이 `__init__()`을 새로 정의하면서 부모 생성자를 호출하지 않기 때문입니다. 다음 정의의 `super().__init__()`은 이를 호출합니다.
- **Q. 마지막 `DrawSinusoidal3`에서 `ts`가 사인과 코사인에 모두 적용되나요?** A. 아닙니다. 새 `calc_sin()`은 `self.ts`를 쓰지만 상속된 `calc_cos()`는 0.01을 사용합니다.
- **Q. 같은 이름의 클래스를 재정의하면 이전 인스턴스도 바뀌나요?** A. 아닙니다. 이름이 새 정의를 가리키게 될 뿐, 기존 인스턴스는 생성 당시의 클래스에 속합니다.

## 실행 환경과 검증 상태

- 두 노트북 메타데이터에는 Python **3.10.12**, 커널 이름 **`data-analysis`**가 기록되어 있습니다.
- 코드는 NumPy와 Matplotlib을 사용하며, 노트북을 열고 실행하려면 Jupyter 환경과 해당 패키지를 사용할 수 있는 커널이 필요합니다.
- 기존 로컬 안내는 `source ~/venvs/data-analysis/bin/activate` 후 `jupyter notebook`을 실행하는 방식입니다. 가상환경 파일의 존재와 별개로, 기록된 커널이 그 환경에 연결되어 있는지와 필요한 패키지가 설치되어 있는지는 미검증입니다. 다른 환경에서는 해당 경로를 그대로 사용할 수 없습니다.
- 노트북에는 저장된 셀 출력과 그래프가 있습니다. 이번 문서 보완에서 셀을 재실행하지 않았으므로 현재 환경의 실행 성공을 새로 확인한 것은 아닙니다.
