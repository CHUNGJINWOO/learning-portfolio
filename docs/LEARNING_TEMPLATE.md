# 📝 학습 문서 표준 템플릿 (Learning Document Template)

본 문서는 `learning-portfolio`의 각 도메인(`01`~`06`)에 작성되는 학습 노트, 기술 분석서, 실습 가이드의 **표준 마크다운 템플릿 및 작성 지침**입니다.

모든 항목을 필수로 강제하지 않으며, 학습의 성격(심층 이론, 단일 실습, 트러블슈팅, 코드 분석)에 따라 필요한 섹션을 유연하게 선택하여 작성합니다.

---

## 📌 3개 독립 영역 검증 상태 모델 (Core Verification Model)

학습의 깊이와 기술적 검증 수준을 왜곡 없이 정직하게 표현하기 위해 다음 **3개 독립 영역**을 채택합니다. 기본 양식은 모든 체크박스가 미선택(`[ ]`) 상태이며, 실제 확인된 항목만 명시적으로 체크합니다.

### 1. 기본 서식 (Default Skeleton)

```markdown
### 📊 검증 및 학습 상태

#### A. 학습 기록 (Learning Record)
- [ ] **개념 학습**: 핵심 원리 및 수학적/이론적 배경 학습
- [ ] **코드 분석**: 예제 코드의 제어 흐름 및 API 호출 구조 분석
- [ ] **직접 구현**: 스켈레톤 없이 자체 코드로 재작성
- [ ] **복습 및 이해도 확인**: 복습 질문 자가점검 및 설명 가능 여부 확인

#### B. 기술 검증 (Technical Verification)
- [ ] **구문 검사 (Syntax)**: 인터프리터 컴파일/구문 오류 0건
- [ ] **빌드 (Build)**: 빌드 시스템(colcon 등) 정상 통과
- [ ] **실행 (Execution)**: 로컬 노드 기동 및 터미널 출력 확인
- [ ] **시뮬레이션 (Simulation)**: Gazebo / Turtlesim 시뮬레이션 환경 검증
- [ ] **실제 하드웨어 검증 (HW)**: 실제 물리 로봇/보드 기기 연동 검증

#### C. 확인 필요 사항 (Caveats & Pending)
- **미검증 항목**:
- **검증 불가 사유**:
- **재검증 필요 조건**:
- **참고 출처 및 근거**:
```

### 2. 가상 작성 예시 (Illustrative Virtual Example Only)

> 💡 **주의**: 아래 블록은 문서 작성 방식을 보여주기 위한 **가상 예시**이며 실제 검증 기록이 아닙니다.

```markdown
### 📊 검증 및 학습 상태 [가상 예시]

#### A. 학습 기록 (Learning Record)
- [x] **개념 학습**: 핵심 원리 및 수학적/이론적 배경 학습 완료
- [x] **코드 분석**: 예제 코드의 제어 흐름 및 API 호출 구조 분석 완료
- [ ] **직접 구현**: 스켈레톤 없이 자체 코드로 재작성 (진행 예정)
- [ ] **복습 및 이해도 확인**: 복습 질문 자가점검 및 설명 가능 여부 확인 (미진행)

#### B. 기술 검증 (Technical Verification)
- [x] **구문 검사 (Syntax)**: `python3 -m py_compile` 통과
- [x] **빌드 (Build)**: `colcon build --symlink-install` 성공
- [x] **실행 (Execution)**: 터미널 로컬 노드 기동 및 로그 출력 확인
- [ ] **시뮬레이션 (Simulation)**: Gazebo / Turtlesim 시뮬레이션 환경 검증 (해당 없음)
- [ ] **실제 하드웨어 검증 (HW)**: 실제 LIMO Pro 로봇 기기 검증 (미진행)

#### C. 확인 필요 사항 (Caveats & Pending)
- **미검증 항목**: 서비스 타임아웃 및 네트워크 단절 시 예외 처리 로직
- **검증 불가 사유**: 실기기(LIMO Pro) 접근 환경 미비
- **재검증 필요 조건**: 로봇 하드웨어 Wi-Fi 연결 및 배터리 전원 인가 시
- **참고 출처**: ROS 2 Humble 공식 튜토리얼 (docs.ros.org)
```

> [!IMPORTANT]
> - **AI 생성 문서와 학습 완료 분리**: AI가 작성한 문서나 요약본만으로 학습 완료를 인정하지 않습니다. 학습자가 실제로 학습하고 검증 근거가 확보된 항목만 체크합니다.
> - **미검증 항목 처리**: 확인되지 않은 항목은 결코 `PASS`나 `[완료]`로 표기하지 않고 체크박스를 비워두거나 `[미검증]` 상태로 명시합니다.
> - **기존 표기 보존**: 기존 문서의 `[미검증]`, `[교재 코드 분석 완료]` 등 원래 표기는 훼손하지 않고 그대로 보존합니다.
